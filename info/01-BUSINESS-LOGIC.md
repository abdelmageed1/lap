# منطق البيزنس — كيف يعمل المعمل

## دورة الحياة الكاملة لزيارة مريض

```
تسجيل الدخول
     ↓
[استقبال] بيانات المريض + التحاليل المطلوبة + الدفع
     ↓
حفظ الزيارة → فاتورة PDF + ملصقات باركود تُفتح تلقائيًا
     ↓
[نتائج - إدخال] فني المعمل يدخل قيم كل معيار
     → حفظ مسودة (يمكن إكمالها لاحقًا)
     → حفظ وإرسال للمراجعة
         ↓
[نتائج - مراجعة] مسؤول آخر يراجع ويعتمد
     → إرجاع للتعديل (لو في خطأ)
     → اعتماد + طباعة تقرير PDF
```

> **قاعدة ذهبية**: لا يُنشأ ملف PDF للنتيجة إلا بعد الاعتماد — مضمون بالكود لا بالتعليمات.

## حالات التحليل المطلوب (visit_test_orders.status)

| الحالة | المعنى | من يُغيّرها |
|---|---|---|
| `Ordered` | طُلب التحليل، لم تُدخَل نتيجة بعد | تلقائي عند حفظ الزيارة |
| `InProgress` | مسودة — قيم جزئية مُدخَلة | فني المعمل (حفظ كمسودة) |
| `Completed` | كل القيم مُدخَلة، بانتظار المراجعة | فني المعمل (إرسال للمراجعة) |
| `Reviewed` | معتمد نهائيًا — يُسمح بإنشاء PDF | المراجع (اعتماد) |

الانتقال `Completed → Reviewed` هو الوحيد الذي يُنشئ PDF وهو **أحادي الاتجاه** (يمكن الإرجاع لـ `InProgress` بصلاحية خاصة فقط).

## قواعد التسعير

- كل تحليل له **سعر مختلف لكل جهة إحالة**: فردي، تأمين، جهة خارجية، إلخ.
- عند اختيار المريض لجهة إحالة في الاستقبال، يُجلب السعر المناسب تلقائيًا من `price_list_items`.
- لو ما في سعر مسجَّل لجهة الإحالة المحددة، يُرجع السعر الفردي (Individual) كاحتياط.
- الخصم يُطبَّق على الإجمالي ويُسجَّل في `visits.discount_amount`.
- الدفعات قابلة للتجزئة — مريض يدفع جزء الآن وجزء لاحقًا — كل دفعة سطر في جدول `payments`.
- المتبقي = `total_amount - discount_amount - SUM(payments.amount)`.

## الحسابات التلقائية (auto_calc)

بعض التحاليل فيها معايير **تُحسَب** من معايير أخرى بدل أن يُدخلها الفني يدويًا:

### CBC (صورة دم كاملة)

| المعيار المحسوب | المعادلة |
|---|---|
| HCT | `HB × 3.1` |
| Color Index | `(HB ÷ 16) × 100` |
| MCH | `(HB × 10) ÷ RBC` |
| MCHC | `(HB × 100) ÷ HCT` |
| MCV | `(HCT × 10) ÷ RBC` |
| Segmented Count | `Seg% × WBC × 10` |
| Lymphocyte Count | `Lymph% × WBC × 10` |
| Monocyte Count | `Mono% × WBC × 10` |
| Eosinophil Count | `Eso% × WBC × 10` |
| Basophil Count | `Baso% × WBC × 10` |

### Creatinine Clearance (تصفية الكرياتينين)

| المعيار | المعادلة |
|---|---|
| Creatinine Clearance | `(Urine Creatinine × Volume) ÷ (Serum Creatinine × 1440)` |
| Daily Excretion (ucrea) | `(Urine Creatinine × Volume) ÷ 100000` |

**الآلية**: عند حفظ نتيجة تحليل CBC أو Creatinine Clearance، تُستدعى `auto_calc.run_auto_calc()` تلقائيًا — تكتشف أي معايير محسوبة وتملأ قيمها وتحدد الـ flag (High/Low/Normal) بناءً على المدى الطبيعي للسن والنوع.

## علامات النتيجة (Flags)

لكل قيمة رقمية مُدخَلة يُحسَب الـ flag تلقائيًا:

| Flag | المعنى | الشرط |
|---|---|---|
| `Normal` | ضمن المدى | `low ≤ value ≤ high` |
| `High` | مرتفع | `value > high` |
| `Low` | منخفض | `value < low` |
| `Abnormal` | غير طبيعي (للنصي) | النص لا يطابق القيمة الطبيعية |
| `Manual` | بدون مدى مرجعي | لا يوجد مدى للمقارنة |

المدى الطبيعي يختلف حسب **النوع (Male/Female/Both)** والفئة العمرية — يُختار المدى الأنسب لكل مريض بمقارنة سنه ونوعه مع كل سطر في `parameter_reference_ranges`.

## نظام الصلاحيات

كل مستخدم له **دور** (Role) والدور له **صلاحيات لكل شاشة**:

| الشاشة (module_key) | وصف |
|---|---|
| Dashboard | لوحة المتابعة |
| Reception | استقبال |
| Visits | زيارات وفواتير |
| Results | نتائج التحاليل |
| PatientHistory | سجل المريض |
| Catalog | كتالوج التحاليل |
| Pricing | الأسعار |
| Settings | الإعدادات |
| Users | المستخدمون والأدوار |
| Audit | سجل التدقيق |
| Backup | النسخ الاحتياطي |
| Reports | التقارير والإحصائيات |

لكل شاشة 4 مستويات صلاحية: **عرض / إضافة / تعديل / حذف**.  
القائمة الجانبية تعرض فقط الشاشات التي للمستخدم صلاحية **عرض** فيها.

### الأدوار الافتراضية

| الدور | الوصف |
|---|---|
| مدير النظام | كل الصلاحيات بلا استثناء |
| مدير المعمل | كل الصلاحيات عدا إدارة المستخدمين (عرض فقط) |
| استقبال | استقبال + زيارات + كتالوج (عرض) + سجل المريض |
| فني معمل | نتائج + كتالوج (عرض) + سجل المريض |

## تنبيهات مطابقة النوع (Gender Validation)

عند إضافة تحليل في الاستقبال، يتحقق النظام من توافق التحليل مع نوع المريض:

- **BHCG / Pregnancy + ذكر** → تنبيه تأكيد قبل الإضافة
- **PSA / Prostate + أنثى** → تنبيه تأكيد قبل الإضافة

التنبيه لا يمنع الإضافة — بل يطلب تأكيدًا واعيًا، لأن حالات استثنائية قد تبرر الإجراء.

## سجل التدقيق (Audit Log)

**كل** عملية إضافة / تعديل / حذف / دفع / اعتماد تُسجَّل تلقائيًا في `audit_logs` بـ:
- من نفّذها (`user_id`)
- متى (`timestamp` UTC)
- على أي سجل (`table_name` + `row_id`)
- ماذا فعل (`action`)
- تفاصيل نصية اختيارية (`details`)

**قاعدة مهمة**: `log_action()` تُستدعى دائمًا **داخل نفس اتصال قاعدة البيانات** الخاص بالعملية الأساسية (بتمرير `conn`) لتفادي `OperationalError: database is locked` في SQLite.
