# دليل الشاشات — من يفتحها وماذا تعمل

## شاشة تسجيل الدخول — `login_window.py`

**من يستخدمها:** الجميع  
**ما تفعله:**
- يُدخل المستخدم اسم الدخول وكلمة المرور
- تتحقق من الهوية عبر `auth_service.authenticate()` (bcrypt hash)
- لو نجح الدخول، تُحدَّد صلاحيات المستخدم من `role_permissions` وتُمرَّر لكل الشاشات كـ `current_user`
- لو الحساب معطَّل (`is_active = 0`) → رسالة خطأ واضحة

---

## لوحة المتابعة — `dashboard_view.py`

**الصلاحية:** `Dashboard → can_view`  
**ما تعرضه (9 بطاقات KPI):**

| البطاقة | المصدر |
|---|---|
| زيارات اليوم | `visit_service.get_daily_visits_count()` |
| إيرادات اليوم | مجموع المبالغ المدفوعة اليوم |
| زيارات الأسبوع / الشهر | مقارنة بنفس الفترة الشهر الماضي |
| إيرادات الأسبوع / الشهر | نفس المصدر |
| مبالغ متبقية | زيارات `balance > 0` |
| نتائج قيد الانتظار | `status IN ('Ordered', 'InProgress', 'Completed')` |
| إجمالي المرضى | `COUNT(*) FROM patients` |

**كل بطاقة قابلة للضغط** → تفتح `DashboardVisitsTableDialog` بقائمة تفصيلية  
**الرسم البياني:** `QtCharts` — مخطط عمودي لإيرادات آخر 7 أيام  
**التصدير:** زر CSV لتصدير بيانات الجدول

---

## الاستقبال — `reception_view.py`

**الصلاحية:** `Reception → can_add`  
**الخطوات الثلاث:**

### 1. بيانات المريض
- الاسم، اللقب، النوع، السن، التليفون
- **كشف مريض موجود**: عند كتابة تليفون مسجَّل مسبقًا:
  - زر **"استخدام بياناته"** → يملأ الحقول تلقائيًا ويربط الزيارة بنفس `patient_id`
  - زر **"عرض سجله"** → يفتح تاريخ المريض دون الخروج من الشاشة

### 2. التحاليل المطلوبة
- بحث نصي (2 حرف على الأقل) → نتائج فورية من `catalog_service.search_tests()`
- تنبيه تلقائي لو التحليل غير مناسب لنوع المريض (BHCG/PSA)
- السعر يُجلب تلقائيًا حسب جهة الإحالة المختارة

### 3. الدفع والحفظ
- إجمالي، خصم، مدفوع، متبقي — كلها تُحسَب تلقائيًا
- **حفظ الزيارة**: يُنشئ `invoice_number` تسلسلي، يحفظ في `visits` + `visit_test_orders`، ينشئ فاتورة PDF وملصقات باركود

## الزيارات والفواتير — `visits_view.py`

**الصلاحية:** `Visits → can_view`  
**ما تعرضه:** كل الزيارات مع أعمدة: رقم الفاتورة، المريض، التاريخ، الإجمالي، المدفوع، المتبقي  
**عمليات:**
- **بحث** بالاسم أو فلترة "مبالغ غير مسددة فقط"
- **اختيار زيارة** → تفاصيلها في اللوح الأيمن (التحاليل المطلوبة وحالتها)
- **تسجيل دفعة** → يُضاف سطر في `payments` ويُحدَّث `paid_amount`
- **إعادة طباعة الفاتورة** → يُعاد توليد PDF من نفس البيانات

## نتائج التحاليل — `results_view.py`

**الصلاحية:** `Results → can_add/can_edit`  
**3 تبويبات:**

### تبويب 1: إدخال النتائج
- قائمة التحاليل بحالة `Ordered` أو `InProgress`
- عند اختيار تحليل → نموذج بكل معاييره مع المدى الطبيعي للمريض
- **حفظ مسودة** → status = `InProgress`
- **إرسال للمراجعة** → status = `Completed`
- الحسابات التلقائية (CBC / Creatinine Clearance) تعمل عند الحفظ

### تبويب 2: المراجعة والاعتماد
- التحاليل بحالة `Completed`
- القيم تظهر مع الـ flag الملوّن (أحمر للغير طبيعي)
- **اعتماد + PDF** → status = `Reviewed`، يُنشأ PDF ويُفتح تلقائيًا
- **إرجاع للتعديل** → status = `InProgress`

### تبويب 3: النتائج المعتمدة (إعادة فتح 🔓)
- للأدمن فقط (`can_delete = 1`)
- يمكن إعادة فتح نتيجة معتمدة لتعديلها بعد كلمة سر الأدمن

## كتالوج التحاليل — `catalog_view.py`

**الصلاحية:** `Catalog → can_view/can_add/can_edit`  
**4 تبويبات:**

### التحاليل والأسعار
- بحث + فلترة بالقسم + عرض المعطَّلة
- اختيار تحليل → معاييره ومداه الطبيعي وأسعاره
- إضافة/تعديل/حذف معيار، مدى طبيعي، سعر
- إضافة تحليل جديد كامل من الصفر

### الأقسام
- إضافة/حذف أقسام معملية

### الأطباء وجهات الإحالة
- إضافة/تعطيل أطباء وجهات إحالة (الحذف الفعلي يُقيَّد لو في زيارات مرتبطة)

### التقارير (Reports)
- إحصائيات الكتالوج وأكثر التحاليل طلبًا

## المستخدمون والأدوار — `users_view.py`

**الصلاحية:** `Users → can_add/can_edit/can_delete`  
**تبويب 1: المستخدمون**
- إضافة مستخدم جديد (username + full_name + password + role)
- تعطيل/تفعيل حساب
- تغيير اسم الدخول (يتطلب كلمة سر الأدمن)
- تغيير كلمة المرور (يتطلب كلمة سر الأدمن)
- حذف مستخدم (مع تأكيد مزدوج + كلمة سر الأدمن)

**تبويب 2: الأدوار والصلاحيات**
- إضافة دور جديد بأي اسم
- مصفوفة صلاحيات لكل شاشة × 4 مستويات
- حفظ الصلاحيات يُطبَّق فورًا (بدون إعادة تشغيل)
